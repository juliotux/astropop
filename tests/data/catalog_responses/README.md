# Catalog response fixtures

`tests/test_catalogs_online.py` runs the same catalog tests in two modes:

```sh
# Replay saved HTTP responses; an unknown request fails without network access.
pytest tests/test_catalogs_online.py

# Use the real services, without response playback or Astroquery result caches.
pytest tests/test_catalogs_online.py --remote-data=any

# Query the other services while skipping potentially slow Gaia requests.
pytest tests/test_catalogs_online.py --remote-data=any --skip-gaia-online
```

`--skip-gaia-online` skips only the eight live Gaia catalog tests. The local
pagination, launcher and timeout tests still run. Without `--remote-data=any`,
the option has no effect: all Gaia tests run against the saved responses.
It also skips Gaia fixture refreshes when used with `--record-catalogs`.

CI runs live service checks, including Gaia, only in the separate
`online_conformance` job using the Linux/Python 3.14 `py314-catalogs-online`
environment. That job runs only `tests/test_catalogs_online.py`. The regular
Python matrix (including 3.14), development dependency jobs, macOS, Windows and
coverage use the saved responses. To run the conformance job locally:

```sh
tox -e py314-catalogs-online
```

Responses are grouped by catalog: `simbad.yaml`, `gaia.yaml`, and one file for
each VizieR catalog, such as `ucac4.yaml`, `twomass.yaml` and `skymapper.yaml`.
The fixture loads these together so catalog queries can share SIMBAD name
resolution responses without duplicating them across files. Recording routes
each response to its catalog automatically.
VCR intercepts HTTP; Astroquery still constructs queries and parses the results.
Requests are matched by URL, method and body, so different catalogs, coordinates,
filters and pagination cursors cannot silently receive an unrelated response.
Repeated tests reuse the same examples. Gaia catalog tests use synchronous
queries in both modes, including a field exceeding the 2000-row per-page limit.
This avoids waiting on ESA's asynchronous queue when refreshing the examples.
SIMBAD's simple SELECT column lists are compared without regard to order:
Astroquery builds some of them from sets, while Astropop accesses fields by name.
Expressions and query criteria still have to match.

To refresh responses, run:

```sh
pytest tests/test_catalogs_online.py --remote-data=any --record-catalogs
```

Recording always contacts the services and replaces examples for requests it
observes. A selection with `-k` updates just those examples. To rebuild all
examples without retaining unused requests, remove the YAML response files
before a full recording. Record in one pytest process; concurrent writers to
these files are unsupported.
Review fixture changes and run the offline suite before committing them.

The serializer keeps one response per request. Separate deterministic tests
cover Gaia's default async launcher, pagination failures and timeout handling.
Gaia's import-time status announcement is suppressed in both modes because it
is unrelated to catalog queries and runs before test fixtures can intercept
requests.

These examples depend on the requests generated by Astroquery. An upstream query
or endpoint change can require a refresh; missing examples deliberately fail
instead of falling back to the network. Authorization and cookie headers are
excluded from recordings.
